# Shards - Domain Contract

> Единственный источник правды по бизнес-логике.
> Код противоречит документу → код неправ.
> Документ неполон → дополни ПЕРЕД кодом, не после.

Версия: 2.3.1
Статус: frozen

---

## 0. Зачем это приложение

Существующие трекеры привычек, финансов и задач работают в изоляции.
Человек держит 3-5 приложений и не видит общей картины.

**Shards** - одна экосистема, где все важные пользователю действия
в разных сферах жизни напоминают о себе и требуют соблюдения баланса
между собой.

### 0.1. Правила игры

1. **Нет накопительных счётчиков** (XP, level, achievements).
   Прогресс - только текущее состояние векторов и целей.
2. **Нет пауз и штрафов.** Любой пропуск - пропуск.
   Векторы восстанавливаются временем.
3. **Прогресс цели обновляется только вручную.**
   Приложение не засчитывает успех автоматически.

## 2. Словарь домена

### 2.1. Vector (Вектор)

Сфера жизни, на которой пользователь хочет сфокусироваться.
Примеры: "Карьера", "Финансы", "Спорт", "Музыка", "Пет-проект",
"Программирование", "Семья".

Состояние вектора S_v - вычисляемое (§3.4). Не хранится в сущности.

- 0-100 - обычный диапазон (за счёт рутинных шагов).
- 100-120 - сверхпродуктивность (за счёт продвижения целей).

Хранимые данные вектора: id, title, emoji, createdAt

Идея в том, что для поддержания высокого значения вектора необходимо
регулярно совершать шаги в рамках привязанных к нему целей.
Это раскрывает главный смысл приложения - пользователь постоянно
должен доказывать себе действиями, что он работает над целями,
даже если количество конкретных шагов до достижения цели
нельзя измерить.

**Вектор - сущность.** Пользователь создаёт свои векторы сам.
Есть пресет по умолчанию ("Здоровье", "Карьера", "Проекты"),
который создаётся при первом запуске. Пользователь может
добавлять, переименовывать, удалять векторы.

**Служебное.** createdAt: ISODateTime - момент создания. Поле ставится системой, а не пользователем. Иммутабельно.

### 2.2. Goal (Цель)

Фрагмент декомпозиции вектора и основание для создания шагов.

Формулируется в виде измеримой величины. Имеет:

- **Название** - строка с формулировкой.
- **Приоритет** - число 1..N, где 1 - высший. Приоритеты внутри
  одного вектора непрерывны (1..N без дырок).
- **Единица измерения** - заполняется вручную, нужно для понятного отображения измеряемой величины.
- **Прогресс** - текущее и целевое значения (`current` / `target`).

Обновление прогресса: current обновляется только вручную пользователем (§0.1). Приложение не интерпретирует current и не выводит из него производных решений. Семантику (растёт/падает, рекорд/сумма) определяет пользователь.

Достижение цели. Не детектится автоматически. Пользователь помечает цель как достигнутую отдельным действием → achievedAt: ISODateTime | null.

Примеры: "Написать 100 битов", "Пробежать 3 км за 10 минут",
"Заработать 120 000 за месяц".

Нетрекабельные цели не имеют смысла - если её нельзя измерить
числом, это не цель. "Стать музыкантом" без цифр - не цель.

### 2.3. Step (Шаг)

Регулярное или одноразовое действие для достижения цели.

- Имеет название.
- Привязан к цели (обязательно). Вектор шага определяется
  через цель.
- **Расписание:** ежедневно / по дням недели / раз в N дней /
  одноразово (на конкретную дату).
- По выполнению шага каждый раз предоставляется возможность
  изменить текущий прогресс цели, если выполнение шага его изменило.

**Одноразовые шаги** решают задачу, для которой раньше
планировалась отдельная сущность Quest. Например: "Снять сниппет
сегодня" - цель вектора "Музыка", в ней одноразовый шаг на дату.
Никаких отдельных квестов не нужно.

Алгоритм расписания. Шаг считается запланированным на дату d, если:

daily — всегда;

weekly — weekdayFromDate(d) ∈ daysOfWeek;

everyNDays — diffDays(d, step.createdAt) % n === 0;

once — d === onDate.

### 2.4. CheckIn (Отметка)

Факт выполнения шага в конкретный день.

- Хранит заметку о выполнении - свободный текст. Примеры:
  "Сегодня бежал плохо, нога болит", "Результаты подходов: 4/4/2/2/1".
  Заметка позволяет отслеживать промежуточные результаты, слишком
  малые чтобы сдвинуть прогресс цели, но важные для сравнения
  и наблюдения.
- Хранит изменение прогресса цели - если пользователь при
  отметке обновил `current` цели, это фиксируется.
- **Нередактируемость.** CheckIn - фиксация факта, не редактируется и не удаляется вручную.
  Поле progressAfter - значение, введённое пользователем в момент
  отметки; оно не является снимком текущего goal.current и не
  меняется при последующих правках цели.

Unique (stepId, date).

### 2.5. Priority (Приоритет)

Приоритет принадлежит цели, не шагу.

- Число 1..N в рамках одного вектора.
- 1 - высший приоритет.
- Непрерывный ряд: при удалении цели все менее приоритетные
  смещаются на 1 вверх (например, удалили цель I → бывшая II
  становится I, III становится II).
- Влияет на вес шага при расчёте daily_score вектора.
  Шаг в цель приоритета I весит больше, чем шаг в цель
  приоритета II.

### 2.6. Daily Score

Вклад вектора в один календарный день `d`. Диапазон 0..120.

Складывается из:

- **Рутинный вклад** - доля выполненных шагов, взвешенная
  по приоритетам целей.
- **Бонус за продвижение целей** - если в этот день пользователь
  обновил прогресс хотя бы одной цели вектора.

Вектор, у которого в день `d` нет запланированных шагов,
не участвует в расчёте `daily_score` для этого дня (см. раздел 3.3).

### 2.7. Отменённые концепции

Зафиксировано в обоснование, чтобы не возвращать случайно.

- **XP / Level** - убраны. Накопительный счётчик создавал "второе
  табло", уводил фокус от шкал. Прогресс целей сохраняется -
  этого достаточно для памяти о результатах.
- **Quest** - убран. Роль выполняют одноразовые шаги.
- **Dream / Milestone** - слиты в Vector + Goal. Разделение
  на "мечту" и "шкалу" было искусственным: и то, и то - сфера
  жизни с состоянием и целями.
- **Achievement** - убран. Выполненная цель и есть достижение.
  Отдельная сущность - дублирование. История - это список
  achieved goals.
- **PauseDay** - убран. Выходной - тоже пропуск. Продуктивный
  человек может себе его позволить; приложение честно показывает
  падение и восстановление, но не наказывает и не врёт про поток.
- **Множитель опыта M(S)** - убран вместе с XP.
- **ScaleId как union** - вектор теперь entity, создаётся
  пользователем, `scaleId` - строка.
- **Reward** - убран из MVP. Обратная связь - через состояния
  векторов и историю целей. Вернём после MVP, если понадобится
  внешняя мотивация.

## 3. Математическая модель

Все константы - в `shared/config/balance.ts`.
Балансировать только там. Никаких магических цифр в логике.

### 3.1. Константы баланса

```ts
export const balance = {
  windowDays: 7, // скользящее окно вектора
  scaleMax: 120, // максимум значения вектора
  routinePool: 100, // пул рутинного вклада в daily_score
  goalProgressBonus: 10, // бонус за продвижение одной цели
  goalProgressBonusCap: 20 // кап суммарного бонуса в день
} as const

export const defaultVectors = [
  { title: 'Здоровье', emoji: '🖤' },
  { title: 'Карьера', emoji: '💵' },
  { title: 'Проекты', emoji: '⚡' }
] as const
```

### 3.2. Веса шагов

**Базовый вес цели** с приоритетом `k`:

Гармоническая шкала: цель I в 2 раза важнее цели II, в 3 раза - цели III.
Резче линейной (3:2:1), потому что в жизни разница между приоритетами
качественная, а не «на единичку».

**Вес шага** внутри цели:

priority_importance(k) = 1 / k

Если у цели `g` в день `d` запланировано `S_g` шагов, каждый шаг получает:

w_step(s) = priority_importance(k) / S_g = (1 / k) / S_g

Деление на `S_g` - чтобы суммарный вклад цели не зависел от количества
её шагов. Иначе создание 10 шагов в цель I давало бы в 10 раз больший
вклад, чем 1 шаг. Это стимулировало бы «накрутку» шагов, а не работу.
Один шаг в цель I весит как два в цель II - независимо от того,
сколько шагов в каждой из них.

**Примеры** (3 цели в векторе, по 1 шагу):

| Цель | k   | S_g | w_step |
| ---- | --- | --- | ------ |
| I    | 1   | 1   | 1.0    |
| II   | 2   | 1   | 0.5    |
| III  | 3   | 1   | 0.33   |

Шаг цели I весит в 2 раза больше шага цели II и в 3 раза - шага цели III.

**Примеры** (2 цели, у цели I - 2 шага):

| Цель | k   | S_g | w_step                    |
| ---- | --- | --- | ------------------------- |
| I    | 1   | 2   | 0.5 каждый (суммарно 1.0) |
| II   | 2   | 1   | 0.5                       |

Сумма двух шагов цели I (1.0) = 2 × один шаг цели II (0.5).

### 3.3. Daily Score вектора

**Для вектора `v` в день `d`:**

1. Найти все шаги вектора v, запланированные на день d.

2. Если таких шагов нет → daily_score(v, d) = undefined.
   День не участвует в расчёте значения вектора (см. 3.4).

3. Сгруппировать шаги по целям.

4. Для каждого шага s вычислить вес w_step(s) по формуле 3.2.

5. W_total = Σ w_step(s) по всем шагам дня.

6. routine_score = routinePool × (Σ w_step(s) × done(s)) / W_total,
   где done(s) = 1 если шаг выполнен, 0 иначе.

7. N_updated(v, d) - число уникальных goalId, достижимых через stepId
   CheckIn'ов со progressAfter ≠ null и date = d, где stepId
   принадлежит шагу в векторе v.

8. goal_bonus = min(goalProgressBonus × N_updated,
   goalProgressBonusCap).

9. daily_score(v, d) = min(routine_score + goal_bonus, scaleMax).

**Проверка** (routinePool=100, goalProgressBonus=10, cap=20):

| Сценарий                                   | daily_score |
| ------------------------------------------ | ----------- |
| Все шаги выполнены, цель не обновлена      | 100         |
| Все шаги выполнены, 1 цель обновлена       | 110         |
| Все шаги выполнены, 2+ целей обновлены     | 120 (кап)   |
| Половина веса выполнена, цель не обновлена | 50          |
| Ничего не сделано, 1 цель обновлена        | 10          |
| Нет запланированных шагов                  | undefined   |

### 3.4. Значение вектора на сегодня

Окно - **7 календарных дней**.

Активные дни = дни d в окне [today - 6 .. today],
для которых daily_score(v, d) ≠ undefined.

S_v = (Σ daily_score(v, d) по активным дням) / |Активные дни|

Если |Активные дни| = 0 → S_v = undefined
(вектор не отображается на дашборде).

**Проверка** (windowDays=7, ежедневные шаги, полная рутина = 100):

| Сценарий                             | S          |
| ------------------------------------ | ---------- |
| Всё ок неделю                        | 100%       |
| Один пропуск                         | ~86%       |
| Два подряд                           | ~71%       |
| Неделя пропусков                     | 0%         |
| Месяц пропусков + неделя нормы       | 100%       |
| Всё ок + ежедневное продвижение цели | 120% (кап) |

### 3.5. Пример с неполным расписанием

Вектор с одним шагом «раз в 3 дня». В окне 7 дней - активных дней 2-3.
Остальные дни - `undefined`, исключены из знаменателя.

Если все запланированные дни выполнены - `S_v = 100%`. Вектор не
проваливается из-за того, что шаги не ежедневные.

## 4. Инварианты

Проверяются в тестах.

- Для любого дня `d`, где у вектора есть запланированные шаги: `Σ w_step(s) > 0`.
- `0 ≤ daily_score(v, d) ≤ scaleMax`.
- Приоритеты целей в рамках одного вектора образуют непрерывный ряд `1..N`.
- `Step.goalId` всегда указывает на активную (не achieved) цель.
- Одна `CheckIn` на пару `(stepId, date)`.
- `daily_score(v, d) = undefined` ⟺ у вектора нет запланированных шагов в день `d`.

## 5. Жизненные сценарии

### 5.1. Хороший день

Утро: 2 шага Health - цели I и II вектора Health.

День: 2 шага Career - цели I и II.

Вечер: обновил прогресс цели Career-I.

daily_score Health = 100%. daily_score Career = 110%.

### 5.2. Пропуск одного дня

Не отметил сон. daily_score Health за день = 66.7%
(одна из двух привычек, эта - с приоритетом I).

Через неделю: S Health ≈ 95.2%.

### 5.3. Болезнь

2 недели не отмечался. S Health = 0.

Прогресс целей сохранён.

Восстановление: неделя регулярности → S Health = 100%.

Цена - потерянное время, но без дополнительного штрафа сверх
естественного падения векторов.

### 5.4. Достижение цели

Goal «100 битов», current = 99, target = 100.

Пользователь выполняет шаг, при отметке обновляет current → 100.

Вручную помечает цель достигнутой. Устанавливается achievedAt.

### 5.5. Одноразовый шаг

Цель «Снять сниппет сегодня» в векторе «Музыка».

Внутри - одноразовый шаг с kind: 'once', date = today.

Пользователь выполняет шаг, отмечает, обновляет current → 1/1.

Пользователь вручную помечает цель достигнутой. Попадает в историю.

### 5.6. Вектор с неполным расписанием

Вектор «Спорт», один шаг «раз в 3 дня».

За 7 календарных дней - 2 запланированных дня, оба выполнены.

daily_score = 100 в обоих. Остальные дни - undefined.

S = (100 + 100) / 2 = 100%.

### 5.7. Продвижение двух целей

Вектор Career, цели I и II. Оба шага выполнены.

Обе цели обновлены в этот день.

routine_score = 100, goal_bonus = min(10 × 2, 20) = 20.

daily_score = min(100 + 20, 120) = 120%.

## 6. Что НЕ входит в MVP

- Социальные фичи.
- Синхронизация (только localStorage → затем mock API).
- Мобильное приложение.
- Импорт из других трекеров.
- AI-ассистент.
- Push-уведомления.
- Экспорт в PDF.
- Тёмная тема.
- JournalEntry / дневник заметок.
- DailyReflection (3 вопроса в конце дня).
- Emotion rating у достижения.
- Rewards (призы за состояния векторов).
